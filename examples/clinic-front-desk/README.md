# Worked example: Clinic front desk

One complete project, from the brief to a running application, so you can see every file ProdOps produces.

**Open it in the app:** in the left column, under *Your projects*, choose **Open the worked example**. It is added as a separate project, your own projects are untouched, and opening it twice does not duplicate it. It opens in Development, where **Run current preview** runs the finished application.

**The brief**

> A front-desk tool for a small physiotherapy clinic. The receptionist registers patients, books appointments without double-booking a therapist, and therapists write short visit notes. The clinic owner sees the day at a glance and no-shows drop.

## What is in this folder

| Path | What it is |
| --- | --- |
| `example.json` | The saved project's settings: name, brief and review decisions. |
| `project/specs/` | Every spec file for the five roles (business, design, development, quality, delivery): `shape.md`, `references.md`, `standards.md`, `plan.md` for each step, plus the scope, requirements and the code standards with their `index.yaml`. Includes the data model (`specs/business/data/shape.md`, `specs/development/database/shape.md`). |
| `project/design/` | Design tokens (`design-tokens.json`, `design-tokens.css`), the design-system reference, its HTML page and the agent rules. |
| `project/solution/` | The finished application: `index.html`, `styles.css`, `app.js`. |
| `handoff-pack/` | What **Download agent pack** produces beyond the files above: `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `brief.md`, `READINESS.md`, `TRACEABILITY.md`, `build-plan/prd.md` and `prd.html`, a prompt for each of the six milestones, and each milestone's log. The skills in `.agents/` are not repeated here; they are the same for every project. |

## How it was made, and what is hand-written

1. The brief was entered in ProdOps and the guided build was followed in a real browser (see `docs/walkthrough/prodops-walkthrough.mp4`). Drafting, standards, the design system, the PRD and the milestone prompts are exactly what the app generated.
2. **Edited by hand in the app:** `business-requirements.md`, `functional-requirements.md`, `design-requirements.md` and `scope.md` (the generated drafts are generic templates, so they were rewritten to describe this clinic), the primary colour (darkened so white text passes 4.5:1), the headline and button label, and a `danger` colour.
3. **Not generated by ProdOps:** `project/solution/` and the six `milestone-log.md` files. An AI assistant wrote the application to match the scope, then wrote the logs afterwards. In real use your coding agent would build each milestone in its own session from its `prompt.md` and write its own log. That agent flow was **not** run here.

## Things to know

- The generated spec drafts are template drafts: "no AI model was used and nothing was validated with real users". Only the four files above were reviewed. Only the Requirements step is marked approved.
- The pack says "Web app (React)". The solution is plain HTML, CSS and JavaScript, so it can run inside the ProdOps preview with no build step. The log for milestone 01 records this.
- The application keeps data in memory. The preview has no browser storage, so everything resets when it closes.
- The preview frame does not allow form submission, so the forms submit from their buttons and the Enter key.

## Checks

- `npm run test:example` runs the application in jsdom (patient and booking rules, status and note rules, a walk through the real page), checks the example is a valid project with no failing or warning readiness checks, and checks the hand-off pack is current.
- The application was also run in a real headless Chrome through the ProdOps preview, and at 375px width (no sideways scroll).
- After changing `project/` or `example.json`, run `npm run example:build` to refresh `handoff-pack/` (hand-written logs are kept).
